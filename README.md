# Cloud Maker

Учебный проект по курсу **«Современные облачные технологии» (2026)**.

**Автор:** Зорин Михаил Иванович.

## О проекте

Cloud Maker — небольшая система управления виртуальными машинами на Linux-хосте. Виртуальные машины запускаются с помощью **QEMU/KVM** и **libvirt**. Управление возможно через CLI, HTTP API (FastAPI) и собственный веб-интерфейс.

Приложение использует системный гипервизор `qemu:///system`. Сервис API работает на самом Linux-хосте, **не в контейнере**. Данные о ВМ (их определения и состояние) считываются из libvirt, поэтому отдельная база данных для их восстановления не нужна.

## Реализованные пункты задания

| Пункт | Возможность | Баллы |
| --- | --- | ---: |
| Обязательное | Запуск ВМ без графического интерфейса через CLI (`scripts/create-vm.sh`) | 4 |
| 1 | HTTP API для создания, запуска, остановки, удаления ВМ | 2 |
| 2 | cloud-init: `hostname`, `ssh_public_key`, `user-data`, ISO с метаданными | 2 |
| 6 | Сохранение и восстановление информации о ВМ и квотах после перезапуска API | 2 |
| 9 | Квоты на суммарные CPU и RAM для ВМ Cloud Maker | 2 |
| 10 | Собственный веб-интерфейс поверх API, отличный от Swagger | 2 |
| 11 | Автоматическая проверка одной командой (`scripts/check.sh`) | 2 |
| 12 | Очистка тестовых ресурсов (`scripts/cleanup.sh`) | 1 |
| **Итого** | **Заявлено к проверке** | **17** |

**Не заявлены:** создание собственных сетей/бриджей (п. 3), контейнерные режимы (пп. 4–5), каталог образов (п. 7), отдельный мониторинг (п. 8).

## Требования

- Linux x86_64 (проверялось на Ubuntu 24.04 LTS).
- Доступ к аппаратной виртуализации (`/dev/kvm`).
- QEMU/KVM, libvirt и сеть libvirt `default`.
- `python3` (рекомендуется 3.12), `python3-libvirt`, `python3-venv`.
- `cloud-localds`, `qemu-img`, `ssh-keygen`, `curl`.
- Доступ пользователя к `qemu:///system` и право записи в `/var/lib/libvirt/images/cloud-maker/api`.

> **Безопасность:** API не содержит авторизации и по умолчанию запускается **только на `127.0.0.1`**. Не публикуйте его напрямую в интернете.

## 1. Установка

```bash
git clone https://github.com/z0r-r01/cloud-maker.git
cd cloud-maker
bash scripts/install.sh
```

Установочный скрипт проверяет архитектуру и KVM, устанавливает системные зависимости, активирует libvirt и сеть `default`, скачивает базовый Ubuntu 24.04 cloud image (с проверкой SHA256) и создаёт SSH-ключ при его отсутствии.

Для API также нужна отдельная директория с правом записи для пользователя, запускающего сервис. Если она ещё не создана, выполните:

```bash
sudo install -d -m 0755 -o "$USER" -g libvirt /var/lib/libvirt/images/cloud-maker/api
```

Пользователь должен иметь право управлять системным libvirt; в Ubuntu обычно помогает членство в группе `libvirt` (после изменения групп потребуется новый сеанс входа):

```bash
sudo usermod -aG libvirt "$USER"
```

На некоторых системах настройки доступа к libvirt и прав файлов могут отличаться. **Не запускайте HTTP API под `sudo`** только ради устранения проблем с правами.

## 2. Python-окружение и запуск API

Python-модуль `libvirt` устанавливается системным пакетом `python3-libvirt`. Поэтому рекомендуется виртуальное окружение с доступом к системным Python-пакетам:

```bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -c 'import libvirt; print("libvirt OK")'
```

Запустите API из **корня репозитория**:

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте:

- Веб-панель: `http://127.0.0.1:8000/`
- Swagger-документация: `http://127.0.0.1:8000/docs`
- Проверка работоспособности: `http://127.0.0.1:8000/health`

Проверка через терминал:

```bash
curl -s http://127.0.0.1:8000/health
# Ожидается: {"status":"ok"}

curl -s http://127.0.0.1:8000/vms
# Ожидается: JSON-массив машин Cloud Maker, например []

curl -s http://127.0.0.1:8000/quota
# Ожидаются объекты limits / used / available
```

### HTTP API

| Метод | Адрес | Действие |
| --- | --- | --- |
| `GET` | `/health` | Проверка API |
| `GET` | `/vms` | Список ВМ |
| `GET` | `/vms/{name}` | Состояние ВМ |
| `POST` | `/vms` | Создание и запуск ВМ |
| `POST` | `/vms/{name}/start` | Запуск ВМ |
| `POST` | `/vms/{name}/stop` | Запрос штатного выключения ВМ |
| `DELETE` | `/vms/{name}` | Удаление выключенной ВМ и её файлов |
| `GET` | `/quota` | Суммарные квоты |

Пример создания ВМ (нужна свободная квота):

```bash
curl -sS -X POST http://127.0.0.1:8000/vms \
  -H 'Content-Type: application/json' \
  -d '{"name":"cm-api-example","cpus":1,"memory_mb":512,"disk_gb":5}'
```

Для создания через API **имя должно начинаться с `cm-api-`**. Параметры `hostname` и `ssh_public_key` необязательны: по умолчанию hostname равен имени ВМ, а публичный SSH-ключ считывается из `~/.ssh/cloud-maker-test.pub`. При указании ключа через API используется переданное значение.

Текущие квоты: **4 vCPU / 4096 MiB RAM суммарно**. Они учитывают все зарегистрированные ВМ с префиксом `cm-`, включая выключенные и созданные вручную.

Остановка гостевой ОС через ACPI **асинхронная**: после запроса `POST /vms/{name}/stop` дождитесь состояния `shut_off`, и лишь затем удаляйте ВМ.

## 3. Базовое задание: запуск ВМ из CLI

Базовое задание можно выполнить без HTTP API, через скрипт CLI:

```bash
bash scripts/create-vm.sh cm-cli-demo 1 1024
sudo virsh -c qemu:///system list --all
sudo virsh -c qemu:///system dominfo cm-cli-demo
```

Ожидается, что `cm-cli-demo` появится в списке libvirt. Скрипт создаёт диск из Ubuntu cloud image, передаёт cloud-init и запускает ВМ через `virt-install --import --noautoconsole`. Графический интерфейс для создания не используется.

После демонстрации можно штатно выключить и удалить тестовую ВМ (не забудьте про её диск):

```bash
sudo virsh -c qemu:///system shutdown cm-cli-demo
# Подождите, пока ВМ станет shut off:
sudo virsh -c qemu:///system domstate cm-cli-demo
sudo virsh -c qemu:///system undefine cm-cli-demo
# Проверьте путь перед удалением созданного диска:
# /var/lib/libvirt/images/cloud-maker/cm-cli-demo.qcow2
```

## 4. Автоматическая проверка всех реализованных функций

Это **основная команда для преподавателя**. Запускать из корня проекта:

```bash
./scripts/check.sh
```

Если файл потерял право на выполнение:

```bash
chmod +x scripts/check.sh
./scripts/check.sh
```

Скрипт сам поднимает отдельный экземпляр FastAPI на свободном локальном порту, генерирует временный SSH-ключ и создаёт тестовую ВМ с именем `cm-api-check-<случайный идентификатор>`. Запущенный вручную API на порту 8000 останавливать не требуется.

Проверяются:

1. HTTP API и веб-панель `/`.
2. Список ВМ и квоты.
3. Создание и запуск ВМ; параметры CPU/RAM.
4. Наличие qcow2 и содержимого подготовленного cloud-init ISO (hostname, SSH-ключ, instance-id).
5. Запрет повторного создания ВМ с тем же именем и некорректного имени.
6. Запрет превышения суммарных квот CPU/RAM.
7. ACPI-остановка и повторный запуск ВМ.
8. Восстановление состояния и квот после перезапуска HTTP-сервиса.
9. Удаление ВМ и её файлов, восстановление исходной величины свободных ресурсов.

**Ожидаемый результат** при успешной проверке:

```text
[PASS] Все проверки Cloud Maker выполнены успешно.
```

Проверка ACPI может занимать несколько минут: гостевой Ubuntu нужно время на загрузку и выключение. Если тест не пройден, скрипт сообщает причину. Тестовые ресурсы предназначены для автоматической очистки после завершения проверки. Тест содержимого cloud-init ISO не равнозначен проверке SSH-входа внутрь гостя.

## 5. Очистка результатов тестирования

Просмотреть ресурсы, которые можно удалить:

```bash
./scripts/cleanup.sh --dry-run
```

Удалить только тестовые ВМ и диски, оставшиеся после `check.sh`:

```bash
./scripts/cleanup.sh
```

Скрипт запрашивает подтверждение. Для запуска без подтверждения есть `--yes`. По имени выбираются **только** `cm-api-check-<12 hex>` и `cm-api-oversized-<10 hex>`, а в директории `/var/lib/libvirt/images/cloud-maker/api` — соответствующие `.qcow2` и `-seed.iso`.

**Обычные машины (`cm-api-example`, `cm-api-web-test`, `cm-cli-demo`) и базовый образ Ubuntu этот скрипт не удаляет.**

## 6. Как устроен проект

```text
app/
  main.py         FastAPI и HTTP-маршруты
  vm_manager.py   управление libvirt, создание/удаление ВМ, квоты
  cloudinit.py    cloud-init seed ISO
web/
  index.html      собственная веб-панель
scripts/
  install.sh      системные зависимости и базовый образ
  create-vm.sh    базовый CLI-запуск ВМ
  check.sh        единая точка входа для интеграционного теста
  check_api.py    интеграционные проверки
  cleanup.sh      очистка остатков интеграционных тестов
requirements.txt  зависимости FastAPI/Uvicorn
```

ВМ регистрируются через `conn.defineXML(...)`, а их список и характеристики берутся из `libvirt`. Диски API-ВМ сохраняются в `/var/lib/libvirt/images/cloud-maker/api`. Рестарт API не уничтожает уже запущенные ВМ.

## Ограничения

- Предназначено для локального учебного окружения. API не имеет аутентификации; не публиковать в открытой сети.
- В текущей реализации используется стандартная NAT-сеть libvirt `default` (собственный bridge не реализован).
- Поддерживается один Linux-хост; автоматического распределения ВМ по нескольким гипервизорам нет.
- Пункт 5 задания (контейнер с управлением хостовым libvirt) не реализован и не заявлен.
